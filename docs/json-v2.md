# Формат JSON v2

ISPaNo записывает только канонический JSON версии 2. Формат используют CLI, web-интерфейс, Telegram и viewer. Проверяйте `schema_version` перед обработкой файла.

## Корневой объект

| Поле | Тип | Описание |
| --- | --- | --- |
| `schema_version` | integer | Версия формата; текущее значение `2` |
| `exported_at` | string | Время формирования выгрузки в ISO 8601 с часовым смещением |
| `cutoff` | string | Дата отсечения экспорта в ISO 8601 с часовым смещением |
| `source_timezone` | string | IANA-зона, использованная для дат источника |
| `tickets` | array | Массив заявок |

Пример минимальной структуры:

```json
{
  "schema_version": 2,
  "exported_at": "2026-09-21T12:00:00+03:00",
  "cutoff": "2026-09-20T12:00:00+03:00",
  "source_timezone": "Europe/Moscow",
  "tickets": []
}
```

## Объект заявки

Каждый элемент `tickets` содержит:

| Поле | Тип | Описание |
| --- | --- | --- |
| `id` | any | Идентификатор заявки из IntraService без дополнительного преобразования |
| `name` | string or null | Название заявки |
| `description` | string or null | Описание заявки |
| `creator_id` | any | Идентификатор автора из источника |
| `creator_name` | string or null | Отображаемое имя автора |
| `created_at` | string or null | Время создания в ISO 8601, если исходная дата распознана |
| `changed_at` | string or null | Время последнего изменения в ISO 8601, если исходная дата распознана |
| `closed_at` | string or null | Время закрытия в ISO 8601, если исходная дата распознана |
| `status_id` | any | Идентификатор статуса из источника |
| `executor_ids` | array of integer | Уникальные числовые идентификаторы исполнителей |
| `chat` | array | Сообщения и события переписки |
| `raw` | object | Исходная запись IntraService без нормализации |

Если исходную дату нельзя распознать, поле даты сохраняет исходное строковое значение. Если даты нет, значение равно `null`. Нормализованные даты без часового пояса интерпретируются в `source_timezone`.

## Сообщение переписки

Каждый элемент `chat` содержит:

| Поле | Тип | Описание |
| --- | --- | --- |
| `id` | any | Идентификатор комментария из источника |
| `occurred_at` | string or null | Нормализованное время события или исходная нераспознанная строка |
| `date_raw` | string or null | Исходное представление даты |
| `author` | string or null | Автор комментария |
| `text` | string or null | Текст комментария |
| `is_private` | boolean | Признак приватного комментария |
| `events` | any | События, переданные источником без преобразования |

## Файлы и атомарность

При каждом дисковом JSON-экспорте создаётся `tickets_export_ГГГГММДД_ЧЧММСС.json` в `OUTPUT_DIR`. Затем тем же содержимым атомарно заменяется `latest.json`: потребитель получает либо старую полную версию файла, либо новую полную версию, но не частично записанный JSON.

`latest.json` — удобная точка чтения для автоматизации; timestamped-файл — неизменяемый результат конкретного запуска. Telegram формирует JSON v2 в памяти и не создаёт оба файла.

# Результаты ревью

Дата ревью: 07.09.2026.

## Исправлено в текущей версии

1. Проект переведён на читаемый `src/ispano`-layout с разделением настроек, клиента IntraService, парсеров, экспорта, сериализации и Telegram-слоя.
2. GET-параметры пагинации передаются через `params`, а сетевые запросы используют connect/read timeout.
3. Конфигурация больше не завершает процесс во время импорта и не требует Telegram-настроек для CLI-экспорта.
4. Некорректный или пустой `ALLOWED_TELEGRAM_USER_IDS` блокирует запуск бота; проверка выполняется и для `/start`, и для `/export`.
5. Добавлен канонический JSON v2 с timezone, нормализованными датами и сохранением исходного API-объекта в `raw`. Legacy-формат доступен через `--format legacy`.
6. `latest.json` записывается атомарно только после успешного экспорта.
7. Viewer перенесён в `web/`, читает `exports/latest.json`, проверяет схему и не использует `innerHTML` для данных тикетов; прежний XSS-вектор закрыт.
8. README, `.env.example`, Docker CMD и описание расположения экспортов приведены к фактическому поведению.
9. Добавлены unit-тесты для дат, HTML-истории и обоих сериализаторов.

## Остаточные задачи

- Выполнить в окружении с Python/Poetry и Docker: `poetry check`, `python -m unittest discover -s tests`, `docker compose build`.
- В CI добавить линтер и статическую проверку типов, если проект будет развиваться дальше.
- Зафиксировать реальный контракт IntraService тестовыми HTTP-fixture или mock-сессией: названия полей `CreatorId`, `ExecutorIds`, порядок пагинации и cookie авторизации зависят от конкретной установки.
- При необходимости добавить retry с ограничением только для безопасных GET-запросов.

## Ограничения этого ревью

В текущей рабочей среде команды `python`, `poetry` и `docker` недоступны, поэтому итоговая проверка исполнения и сборка образа не запускались. Файлы проверены структурно и добавлены тесты, которые следует прогнать в CI.
